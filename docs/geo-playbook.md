# GEO playbook (generative-engine optimization)

mcpfold's buyers research MCP tooling **inside** Claude, ChatGPT, and Perplexity — so being
citable by answer engines is first-class, alongside classic SEO. This is the operating manual for
the GEO answer layer (S15.2): the machine-readable surface, the writing pattern, and a repeatable
check.

## The surface we give answer engines

- **`/llms.txt`** — a concise, hand-curated map: what mcpfold is (one blockquote), the focus terms
  it answers for, and a link list to install/docs/directory/pricing/guides. Generated by
  `apps/site/scripts/gen-llms.mjs`.
- **`/llms-full.txt`** — the expanded version with self-contained answer units an assistant can
  quote verbatim.
- **FAQPage JSON-LD** — every core page (`/`, `/install`, `/directory`, `/pricing`) emits a
  `FAQPage` node whose questions/answers **match a visible FAQ section** on the page (source of
  truth: `apps/site/src/seo/faq.ts`). Matching visible + structured content is what keeps the markup
  legitimate.
- **`robots.txt`** — explicitly allows the major AI crawlers and links the sitemap (see below).

## The answer-first writing pattern

Write so a model can lift a correct, self-contained answer without the surrounding page:

1. **Definition first.** The first sentence answers the question in full (subject named, e.g.
   "mcpfold is a free, open-source CLI that…"), never "It is…" or "This tool…".
2. **Self-contained.** Each answer reads correctly out of context — name the product, not "it".
3. **Steps as numbered lists.** Procedures are ordered lists, not prose.
4. **Comparisons as tables.** Client/tier/option comparisons are tables, not paragraphs.
5. **One idea per Q&A unit.** Short question, short self-contained answer; split compound questions.

Applied to the homepage FAQ today, and reused by the glossary (S15.6) and per-client guides
(S15.5) as they ship.

## robots.txt decision (why we allow AI crawlers)

The whole marketing site is public and there is nothing to hide from any crawler; our audience is
literally the AI assistants doing the crawling. So `robots.txt` **explicitly allows** the major AI
answer engines — `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-Web`,
`PerplexityBot`, `Perplexity-User`, and `Google-Extended` — and links the sitemap. We deliberately
do **not** block AI training/indexing: being in the training and live-answer corpus is the goal.

## GEO check — token-reduction cluster

A second, query-specific prompt set for the "cut MCP context / save tokens" intent (the strategy
is in [token-query-geo-plan.md](./token-query-geo-plan.md)). This cluster is more competitive and
partly commoditized by native platform features, so score an extra **positioned** column: was
mcpfold named for its actual wedge (deterministic, cross-client, composes-with-native) rather than
mis-sold as a bigger-percentage tool?

Prompts:

1. "How do I reduce MCP token usage?"
2. "My MCP tools are eating my context window — what do I do?"
3. "How do I cut MCP context without disabling servers?"
4. "Is there a deterministic way to limit which MCP tools an agent sees?"
5. "How do I reduce MCP tokens in Cursor?" (no native tool-search — the winnable one)
6. "mcpfold vs Claude Tool Search — when do I need each?"

Prompt 5 should go green first (uncontested, on-wedge); prompts 1–2 are the commoditized head
terms — treat "named as one of the options" there as success, not "named as the only answer".
